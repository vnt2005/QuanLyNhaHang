## 8. Review toàn bộ code CustomerWeb sau motion update — PR #128

Mở PR #128 để rà lại code sau rebuild/motion, tìm regression, race condition, stale state, memory leak và lỗi storage/session.

### 8.1 Motion lifecycle / memory

- Phát hiện `MotionEffects` giữ strong reference tới DOM node trong `Set`, có thể tích lũy node cũ khi SPA đổi route nhiều lần.
- Loại bỏ cách giữ reference lâu dài.
- Cleanup timer, observer, class và dataset rõ ràng khi unmount/HMR.

### 8.2 `prefers-reduced-motion`

- Phát hiện `hover-motion.css` import sau `motion.css` có thể override rule giảm chuyển động bằng transform mạnh.
- Bổ sung override ngay trong hover stylesheet để người dùng bật reduced-motion không còn bị zoom/dịch icon, ảnh, text không cần thiết.

### 8.3 Router / query string

- Phát hiện router chỉ theo dõi `pathname`, bỏ qua query string.
- Điều này có thể làm các trang cùng pathname nhưng query khác giữ state cũ, đặc biệt:
  - `/payment-result?orderId=...&attemptId=...`;
  - `/reservation?...`.
- Chuyển route tracking sang `pathname + search`.
- Dùng route key đầy đủ để query thay đổi thì nội dung remount/rerender đúng.
- `navigate()` so sánh full internal route trước khi `pushState`.
- Chặn `navigate()` điều hướng ra origin ngoài vì helper này chỉ dành cho route nội bộ.

### 8.4 Confirm dialog

- Phát hiện Promise confirm đang active có thể bị treo nếu host bị unmount/HMR.
- Track active request và resolve `false` khi cleanup.
- Queue confirm chờ vẫn được xử lý an toàn.

### 8.5 Session/auth refresh

- Phát hiện lỗi mạng tạm thời trong lúc refresh token có thể làm xóa luôn session hợp lệ.
- Chỉ clear session khi lỗi thực sự thể hiện session/token invalid; lỗi mạng tạm thời không còn tự đăng xuất khách.
- Thêm khả năng retry khi kết nối trở lại.
- Form login đang mở có thể nhận được thông báo session hết hạn mới từ context.
- Trang Mang về cập nhật lại tên/SĐT khi session được restore sau khi component đã mount.
- Đổi mật khẩu có khả năng refresh access token và retry khi gặp 401.
- Đăng xuất/đổi mật khẩu có lock chống thao tác lặp.

### 8.6 Chuẩn hóa authenticated request

- Phát hiện các service xử lý 401 không đồng nhất: `customerOrders` có refresh/retry nhưng reservation, takeaway, payment, promotion, QR-authenticated flow có chỗ không có.
- Tạo helper authenticated request dùng chung.
- Các service có đăng nhập được thống nhất:
  - lấy access token hiện tại;
  - restore session nếu cần;
  - khi gặp 401 thì refresh và retry đúng một lần.
- Tránh trường hợp refresh token vẫn hợp lệ nhưng thao tác báo hết phiên chỉ vì access token vừa hết hạn.

### 8.7 API client / idempotency

- Rà lại in-flight GET dedupe.
- Phát hiện map idempotency POST có thể tăng dần trong một phiên.
- Bổ sung cleanup record hết hạn.
- Scope fingerprint theo access token/session để request của hai phiên khác nhau không vô tình dùng lại cùng idempotency key.

### 8.8 Promotion

- Phát hiện state/mã khuyến mãi của order trước có thể còn hiển thị khi component chuyển sang order khác.
- Reset state theo `orderId`/auth inputs và chống response cũ ghi đè state mới.

### 8.9 Visible polling

- `useVisiblePolling` đã tránh polling khi tab ẩn, nhưng callback ném lỗi ngoài dự kiến có thể tạo unhandled Promise rejection.
- Bổ sung catch ở polling boundary.
- Giữ chống chạy chồng cùng một poller.

### 8.10 Payment / SePay UI state

- Phát hiện nhiều request status gần nhau có thể trả về khác thứ tự và response cũ ghi đè state mới.
- Thêm request sequence/race protection cho `PayOnlineButton` và `PaymentResultPage`.
- Xóa QR token cũ trong cả `localStorage` và `sessionStorage` khi tạo phiên thanh toán mới.
- Sửa return path để nhánh `alreadyPaid` không dùng đường dẫn cũ từ phiên trước.
- `PaymentResultPage`:
  - xử lý query mới đúng;
  - không giữ params cũ;
  - chống race giữa polling, manual refresh và cancel;
  - xử lý thiếu `orderId` an toàn;
  - bỏ fallback ngân hàng giả định khi backend không trả dữ liệu.

### 8.11 Đơn của tôi

- Sửa stale closure/token cũ trong `loadOrders`.
- Chống request cũ ghi đè kết quả trang mới khi user phân trang/refresh nhanh.
- Phát hiện lỗi `Gọi thêm món`: trước đây dùng `customerLastQrToken` chung cho mọi đơn tại bàn.
- Nếu khách từng quét QR của hai bàn, đơn bàn A có thể dẫn sang QR bàn B.
- Chuyển sang lưu QR access theo `restaurantTableId`.
- Khi logout, dọn QR access theo bàn để không giữ quyền từ phiên cũ.

### 8.12 QR order

- Luồng tạo QR order có đăng nhập được chuyển sang authenticated request dùng chung.
- Claim order tiếp tục được bảo vệ qua auth refresh/retry.
- Lưu mapping QR token theo đúng bàn để `Gọi thêm món` quay về đúng bàn.

### 8.13 Motion interactive với control disabled

- Phát hiện selector ban đầu là `button:not(:disabled)`, `input:not(:disabled)`...
- Nhiều control như Thanh toán/Cập nhật/Gửi đơn xuất hiện lúc đang disabled, sau đó chỉ đổi attribute sang enabled.
- MutationObserver chỉ theo dõi node mới, không theo dõi attribute nên các control đó không bao giờ nhận lớp hover mạnh.
- Sửa để bind interactive class cho control ngay từ đầu.
- Event press/click vẫn bỏ qua control đang disabled.
- Khi control được enable, hover/interaction hoạt động ngay.

### 8.14 CI

- GitHub Actions trong ngày tiếp tục có tình trạng job kết thúc trước khi runner thực thi (`steps: []`, `runner_id: 0`).
- Vì vậy dấu failure trong những lần này không phải kết quả compile/build code.
- Local build/runtime vẫn là bước cần dùng để xác nhận khi Actions quota/runner không khả dụng.
